# FilePilot 英语版本实施计划

更新日期：2026-10-10

实施状态：实施中；第一阶段 E02 至 E05、第二阶段、第三阶段 E11 至 E16，以及第四阶段 E17 至 E21 已完成；第一阶段 E01 的改造前基线未留存。

本次只在现有简体中文版本基础上新增英语，不扩展其他界面语言。英语版本覆盖界面、应用生成的系统提示、桌面命令反馈和新任务的 AI 说明，并保留现有中英文目录命名能力。实施优先解除业务判断对中文文案的依赖，再接入语言配置和翻译资源，最后完成桌面安装包与核心流程验收。

## 目标与交付范围

本期支持简体中文 `zh-CN` 和英语 `en`。两种语言共用应用、接口和文件操作逻辑，通过设置切换，不制作两套应用或维护两套页面。

完成后应满足以下条件：

- 用户可以选择简体中文、English 或跟随系统，保存后立即应用到界面，重启后恢复选择。
- 英语覆盖普通整理、一键整理、分类规则、工作区、历史、设置和图标工坊的完整流程。
- 应用生成的错误、扫描进度、预检问题、执行结果、回退反馈和通知能按当前界面语言显示。
- 新任务的 AI 用途摘要、规划解释和图标分析说明默认使用任务创建时的界面语言。
- 用户能够独立选择中文或英文目录命名，界面语言不会改变该选择。
- 中文旧配置、旧会话、旧执行记录和用户自定义内容保持可读可用。
- 发布包包含所需资源，安装器和面向英语用户的使用文档同步完成。

本期不增加第三种界面语言，不扩展目录语言种类，不做历史内容自动翻译，不因语言切换自动修改文件或目录名称，也不建立在线翻译服务。常规开发日志、堆栈和第三方原始诊断保留原始语言；用户可见的概要提示必须本地化。

## 语言行为设计

### 三类语言的职责

| 名称 | 建议字段 | 取值 | 作用 |
| --- | --- | --- | --- |
| 界面语言偏好 | `UI_LANGUAGE` | `system`、`zh-CN`、`en` | 用户保存的应用显示偏好 |
| 实际界面语言 | `resolvedUiLocale` | `zh-CN`、`en` | 本次渲染、格式化和通知使用的语言 |
| 任务内容语言 | `content_locale` | `zh-CN`、`en` | 任务内 AI 生成内容的语言，随任务保存 |
| 目录语言 | 现有 `language`、`LAUNCH_DEFAULT_LANGUAGE` | `zh`、`en` | 新分类目录的命名语言 |

`UI_LANGUAGE` 和 `content_locale` 是本计划提出的新字段，不复用已有目录语言字段。本期不增加独立的 AI 语言设置项，新任务默认取当前实际界面语言。

英语界面允许生成中文目录，中文界面允许生成英文目录。真实文件名、路径、用户输入和已保存的 AI 文本保持原文，界面中出现这些内容不视为漏翻译。

### 首次启动与保存

1. 新安装默认 `system`。根据 `navigator.languages` 的偏好顺序选择首个可支持语言，`en-*` 映射为 `en`，`zh-*` 映射为简体中文 `zh-CN`；都不匹配时使用 `zh-CN`。
2. 桌面版首期使用 WebView 提供的语言偏好，浏览器版使用浏览器偏好。安装包验收时确认 WebView 的实际表现；若与 Windows 显示语言不一致，再增加最小的宿主语言读取能力。
3. 已有配置缺少 `UI_LANGUAGE` 时补 `zh-CN`，保留升级前的中文体验。迁移逻辑必须区分已有配置和全新配置，不能统一套用新安装默认值。
4. 未知或损坏的持久化语言值回落为 `zh-CN`；API 写入不支持的值返回明确的校验错误。
5. 设置页提供“跟随系统 / 简体中文 / English”。语言选择遵循现有草稿与保存流程，保存成功后更新全局语言；保存失败时保持原来的已生效语言。
6. 后端配置是持久化权威，`localStorage` 仅缓存已保存的偏好，用于下次启动。启动后与设置快照核对，避免形成两个独立设置来源。
7. 语言切换不重新挂载整个工作区，不清空表单草稿，不重建任务，不重连或取消正常运行的 SSE 流。

静态导出时先生成中性的启动内容，客户端确定语言后展示界面。两种语言资源直接随构建打包，不依赖外部翻译资源下载。不能仅用 `suppressHydrationWarning` 掩盖正文不一致；需要验证首次加载、缓存恢复和后端不可用时的实际显示。

### 已有任务与进行中的操作

- 创建任务时把 `resolvedUiLocale` 显式传给后端，保存为 `content_locale`。
- 扫描、规划、补充分析和重试均从任务读取该字段，不在调用模型时临时读取可变化的全局设置。
- 用户在任务中切换界面语言后，系统标签和结构化诊断随界面变化；该任务后续 AI 回复继续使用创建时的内容语言。
- 恢复旧任务时尊重原任务。缺少字段的旧任务按 `zh-CN` 解释，正常保存时补齐，不批量重写历史。
- 任务恢复匹配不得因界面语言变化而拒绝继续已有任务；只有明确创建新任务时才采用新的内容语言。
- 分类规则生成等非任务调用，在请求开始时捕获实际界面语言。图标生成批次同样捕获内容语言并随批次或版本保存，进行中不改变语言。
- 请求未带语言的旧客户端或命令入口使用兼容默认值 `zh-CN`，不依赖后端全局语言改变行为。
- 已经发出的桌面通知保留发送时的文字；后续通知使用发送时的界面语言。

## 技术方案

### 前端翻译资源

采用 `i18next + react-i18next`，首批选取与当前 React、Next.js、TypeScript 和静态导出兼容的版本，固定到锁文件并验证构建。使用现有路由，不引入语言 URL 前缀、服务端语言重定向或新页面副本。

建议新增以下结构，文件名在实施时可按现有项目约定调整：

```text
frontend/src/i18n/
  locales.ts
  instance.ts
  provider.tsx
  formatters.ts
  diagnostics.ts
  resources/
    zh-CN/
      common.json
      launcher.json
      workspace.json
      rules.json
      history.json
      settings.json
      icons.json
      diagnostics.json
    en/
      common.json
      launcher.json
      workspace.json
      rules.json
      history.json
      settings.json
      icons.json
      diagnostics.json
```

资源管理规则：

- 使用稳定语义键，例如 `workspace.precheck.highImpactMove`，不使用整句中文作键。
- 英文资源与中文资源具有对应的语义键；复数后缀按语言规则验证，不要求两种语言的物理键完全相同。
- 文件名、路径、数量、耗时和模型名称使用参数插值，句子整体翻译，避免按中文顺序拼接片段。
- 英文数量区分 `1 file` 和 `2 files`；零条、单条、多条都要验收。
- 富文本通过受控组件插值实现，路径和用户文字保持普通文本，不拼接可执行 HTML。
- 组件通过 hook 获取翻译；工具函数使用显式语言或翻译上下文，不在模块初始化时缓存译文。
- 错误、通知、视图模型和派生状态优先保存代码与参数，渲染时翻译，避免切换语言后留下旧译文。
- 缺失英文键在运行时回退中文，CI 对应用自有文案的缺失键报错；未知诊断代码显示当前语言的通用提示。

### 结构化系统诊断

HTTP、SSE、预检、执行记录、回退和 Tauri 命令逐步使用共同的数据形态。以下示例是目标契约：

```json
{
  "code": "HIGH_IMPACT_MOVE",
  "params": {
    "display_name": "project",
    "source": "Downloads/project",
    "reason_code": "PROJECT_DIRECTORY"
  },
  "severity": "warning",
  "related_item_ids": ["F001"],
  "message": "用于兼容旧消费者的消息"
}
```

现有 `error_code`、`reason`、`status`、`issue_type` 可以继续保留。通过集中适配器归一化到可翻译诊断，不为了字段命名一致而重写所有协议。已有跳过项的 `reason` 应直接复用。

新数据在产生位置确定风险代码和关联条目，不从翻译后的字符串提取业务信息。结构化参数应与文件操作使用的真实路径保持清晰边界，不能把“当前目录”“待确认区”等显示标签回传为操作目标。

迁移期间保留现有 `message` 等字段，使前后端可以逐批更新。新前端优先使用结构化诊断；旧记录没有代码时，在集中兼容层做有限映射，不能建立散落各组件的中英文正则判断。无法识别的旧提示保留原文，不猜测其业务含义；原始错误细节放在诊断区域，概要使用当前语言。

Tauri 成功返回状态、代码和参数，失败使用可序列化错误对象，并在 `runtime.ts` 或集中适配层处理拒绝值。图标应用、恢复和抠图的所有调用方同步更新，未知旧字符串使用兼容兜底。文件选择窗口的系统按钮遵循 Windows 自身语言，应用提供的标题、过滤器名称等由应用本地化。

### AI 输出与机器协议

模型指令、工具协议和用户可见内容按字段区分：

| 内容 | 语言处理 |
| --- | --- |
| `suggested_purpose`、`summary`、规划说明、图标 `category` | 使用任务或调用捕获的内容语言 |
| 分类规则初稿 | 使用本次调用的内容语言，保留目录标签和既有规则原文 |
| 图标 `visual_subject` 与需要英文的绘制指令 | 保持英文要求 |
| 工具名、JSON 字段、枚举、文件 ID 和槽位 ID | 保持现有机器协议 |
| 目标目录名 | 使用原有目录语言策略或真实目录名 |
| 无法判断、分析未覆盖等状态 | 使用独立状态或原因字段，不靠中文摘要识别 |

修改所有相关提示入口和重试、修复提示，覆盖文件分析、图片理解、规划、规则初稿及图标概念分析。中文“摘要不超过四十字”与英文摘要的长度要求分别定义，英文应以简短句子或词数约束表达。

规划回复中的 Markdown 标题按内容语言生成。内部消息过滤优先使用现有 `visibility`，需要细分时增加明确的消息类型；旧扫描文本、文件内容分隔符和错误前缀解析留在兼容层，新生成路径使用结构化结果。内部提示词不要求全文改写为英文，语言要求必须明确且不与中文示例冲突。

模型输出不能仅凭提示词保证语言正确。自动测试检查指令传递和协议有效性，真实模型样例用于人工核对语言、术语和长度。语言不符合预期不能改变安全校验、自动放行不合法计划或新增无边界的模型重试。

### 内置内容与用户内容

- 策略模板标题、说明、粒度、前缀和谨慎度的界面名称通过稳定 ID 翻译。
- `strategy-catalog.json` 中的中英文目录名称继续服务目录生成；模型提示片段与界面展示名称分开管理。
- 快照已有 `template_label`、`language_label` 等字段可以兼容保留，新界面根据 ID 生成当前语言标签。
- 图标内置模板名称和说明按模板 ID 提供英文显示；用户编辑后的名称、说明、提示词优先保留其修改。
- 为默认模型预设和内置模板明确“系统默认显示值”与“用户自定义值”的来源，不能通过名称恰好等于某句中文来区分。
- 用户新增预设的建议名称使用创建时的界面语言，保存后作为用户内容处理，不因之后切换语言而改名。
- 待确认区的显示名随语言变化，真实 `Review` 目录名、槽位 ID 和实际目标路径保持现有语义。

### 日期与布局

统一日期、时间、数字、耗时和用于展示的文件排序入口。`utils.ts`、`use-history-list.ts`、图标历史抽屉、来源列表和预览工具中的固定中文 locale 改为实际界面语言。

仅本地化显示和展示排序，不改变时间戳存储、路径比较、ID 分配、恢复签名、执行顺序或回退顺序。语言与时区独立，保留现有时间含义。

英语版检查侧栏、步骤选择、状态标签、按钮、表格、弹窗、设置选项、长路径和预检风险说明。必要时调整换行、最小宽度或文字长度，维持现有视觉体系。至少验收桌面最小窗口 `960 × 640`、默认窗口 `1100 × 720`、浅色与深色主题，以及 Windows 常用缩放比例。

## 兼容策略与风险处理

| 风险 | 处理方式 |
| --- | --- |
| 翻译改变字符串判断 | 先补语义字段与回归测试，再替换文案 |
| 两处语言设置互相覆盖 | 后端配置为权威，缓存只保存已成功提交的偏好 |
| 语言切换丢失草稿或正在执行的任务 | provider 原位更新，保留组件状态和流连接；测试设置保存与工作区状态 |
| 修改 AI 占位词影响安全判断 | 用明确状态替代自然语言占位，先覆盖未分析与无法判断分支 |
| 全局语言影响并发任务 | 每个任务或调用独立捕获内容语言，贯通重试和恢复 |
| 内置模板翻译覆盖用户修改 | 按稳定 ID 和来源元数据区分默认值与用户覆盖值 |
| 旧记录无法完整翻译 | 集中兼容映射，未识别旧内容保留原文，不批量重写或猜测 |
| 英文长文本破坏布局 | 在真实窗口和缩放比例下检查，按控件调整宽度和换行 |
| 开发正常但安装包漏资源 | 静态构建检查、PyInstaller 资源检查和实际安装验证 |

兼容字段至少保留到本期中英文版本验收完成；移除前确认旧数据消费者和前后端打包组合。避免破坏性改写旧配置、旧 journal 或 AI 对话，新增字段以可选默认值承接历史数据。

若某阶段失败，回退该阶段代码和依赖锁文件，保留原始用户数据。默认配置与新增字段必须使旧数据仍可读取。不能通过关闭风险检查、弱化目标目录约束或隐藏未知错误来完成英语验收。
