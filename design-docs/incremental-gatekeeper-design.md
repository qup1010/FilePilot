# FilePilot 定时扫描守门人设计

更新日期：2026-07-26

## 目的

这份文档定义"定时扫描守门人"功能：一个常驻的增量整理机制，定期扫描受管目录（典型为下载目录），对新落地的文件做单文件归位判定，高置信自动移动、低置信不动，并把所有决策（包括"没做什么"）呈现给用户。

守门人不替代现有大扫除模式，两者互补：大扫除负责一次性建立目录骨架，守门人负责此后持续维持整洁。

本文档只覆盖守门人功能本身。产品定位、图标工坊、服务层重构等议题不在范围内。

## 非目标

- 不做实时文件监听（watchdog / ReadDirectoryChangesW），常驻形态为定时轮询。
- 不做多轮对话式规划。守门人的判定是单次结构化调用，不复用 `submit_plan_diff` 会话机制。
- 不设 Review 待确认区。低置信文件留在原地，不移入任何中转目录。
- 第一版不做显式规则编辑器（后续可选）。

## 已定决策记录

以下决策已经过讨论确认，实施时不再重议：

| 决策点 | 结论 | 理由摘要 |
| --- | --- | --- |
| 默认姿态 | 高置信自动移，低置信不动 | 待批清单本身就是新的混乱；文件留在原地是最安全的默认 |
| 冷启动 | 先跑一次大扫除建骨架 | 大扫除定位为安装向导，产出目录结构 + 初始偏好 |
| 模型角色 | 每次都调模型，规则/偏好仅注入 prompt 加速与个性化 | 单文件增量调用成本极低（月级几元），不值得为省钱牺牲质量 |
| 常驻形态 | 定时轮询扫描 | 实现简单一个数量级，天然躲开"文件写入中"边界，且轮询顺带完成纠正采集 |
| 置信来源 | 模型自报置信分，但阈值由影子期实测数据校准 | 自报置信系统性偏高，必须用实测精度校准后才可信 |
| 纠正采集 | 轮询时对账 journal 与实际位置，反推用户挪动 | 零摩擦、零感知，采集率最高 |
| 大扫除交接 | 完成后追加一次调用，反推泛化归类原则 | 一次调用得到可注入 prompt 的偏好描述，而非膨胀的 few-shot 样本 |

## 信任模型

守门人能被放心使用，依赖三根柱子：

1. **规则与记忆**：判断尽量对（偏好注入 + 纠正学习）。
2. **记录呈现**：错了能兜住（时间线 + 单项撤回），且克制可见（跳过项也呈现原因）。
3. **可移动性前提**：只动"此刻可以安全移动"的文件（可移动性门）。

三者缺一不可。自动移动是最后拧开的阀门，不是第一个实现的功能。

## 架构

### 数据流

```
定时器（默认 30 分钟）
  └─ 扫描器：目录快照 diff
       ├─ 新文件 → 可移动性门 → 通过者合并成一次模型判定调用
       │                              ├─ 置信 ≥ 阈值 → 执行移动 + 写 journal + 时间线
       │                              └─ 置信 < 阈值 → 不动 + 时间线记录"暂不处理"
       │        └─ 未通过 → 不动 + 时间线记录跳过原因
       └─ 对账：journal 记录位置 vs 实际位置 → 差异生成纠正记录 → 偏好沉淀
```

### 组件与落位

新增 `file_pilot/gatekeeper/` 包：

| 模块 | 职责 |
| --- | --- |
| `scanner.py` | 目录快照、diff、落地判定（大小连续两轮不变才算落地） |
| `movability.py` | 可移动性门（见下节） |
| `judge.py` | 构造单文件判定 prompt、合并批量调用、解析 `slot_id + confidence` |
| `executor.py` | 复用 `execution/service.py` 的预检与执行，单文件粒度 |
| `reconciler.py` | journal 与实际位置对账，产出纠正记录 |
| `preferences.py` | 偏好存取；纠正累积到阈值后调用模型压缩为泛化偏好文本 |
| `timeline.py` | 决策时间线的读写（移动、跳过、纠正、影子决策统一入此） |
| `runner.py` | 轮询调度、熔断、降级、影子/实弹模式开关 |

复用现有能力：`ai/` 的 provider、`execution/` 的预检与 journal、`rollback/` 的回退、`app/safety.py` 的目录级安全检查（作为守门人受管目录准入的前置校验）。

### 可移动性门

在模型判定之前先过的本地事实检查，模型无法也不应判断这些：

| 信号 | 规则 | 实现 |
| --- | --- | --- |
| 冷却期 | 落地不满 24 小时（可配置）不动 | mtime 比较 |
| 占用探测 | 独占方式打开失败 → 本轮跳过 | Windows 独占 open 尝试 |
| 成套文件 | 同名异扩展（`X.mkv`+`X.srt`）、`X.html`+`X_files/`、含 `.dll` 同级的 `.exe` → 整组不动 | 文件名模式匹配 |
| 云占位文件 | OneDrive 按需文件占位符不动 | `FILE_ATTRIBUTE_RECALL_ON_DATA_ACCESS` 属性检测 |
| 目录级安全 | 受管目录本身须通过 `unsafe_source_path_reason` | 复用现有 safety |

门的输出：`movable: bool + skip_reason`。未通过者记入时间线，跳过原因用户可见。

### 判定调用

- prompt 结构：稳定前缀（目标目录清单及语义 + 偏好摘要 + 系统规则，走 prompt cache）+ 本轮待判文件的元信息（名称、大小、类型、来源域名如可得）。
- 同一轮多个文件合并为一次调用，输出为每文件 `{item_id, slot_id | null, confidence}`。
- `slot_id` 必须来自目录清单（沿用现有 item_id registry 思路，拒收幻觉目标）。
- 模型说"不确定"（`slot_id: null`）一律不动——模型的否决权绝对，但它的确信要过阈值这一关。

### 置信阈值校准

- 初始阈值保守（建议 0.9 起步）。
- 时间线上每条自动移动都可被纠正采集捕获；按置信分段统计实测精度（模型报 0.9 的判断实际被纠正比例）。
- 阈值调整基于实测精度表，目标：自动移动段实测精度 ≥ 95%。
- 同一类判断被纠正 ≥ 2 次，该类（按目标 slot + 文件类型聚合）降级为"不动"。

### 影子模式

实弹之前必经阶段，默认运行 1~2 周：

- 完整跑扫描、可移动性门、模型判定，但不移动任何文件。
- 时间线展示虚拟决策："本会把 X 移到 Y（置信 0.87）"，用户单击"对/不对"反馈（必须是单击级操作）。
- 影子期产出：初始置信-精度曲线 → 决定实弹阈值；同时建立用户信任。
- 影子转实弹是用户显式操作，不自动切换。

### 熔断与降级

| 场景 | 行为 |
| --- | --- |
| 单轮新文件数 > 阈值（默认 50） | 本轮不逐个处理，托盘提示"检测到大批新文件，建议运行完整整理" |
| 模型 API 不可用 | 本轮全部不动，托盘标注离线状态；不做任何"猜测性"移动 |
| 连续 N 轮调用失败 | 暂停轮询并通知，等待用户处理配置 |
| 执行中单文件失败 | 记录失败原因入时间线，不影响同轮其他文件 |

### 纠正采集与偏好沉淀

- 每轮轮询顺带对账：journal 中"守门人移动到 A"的文件，实际出现在 B → 生成纠正记录（原判定、用户去向、文件特征）。
- 文件身份追踪：journal 需增加 size + mtime + 小文件（< 4MB）内容 hash 字段，以便跨改名识别。
- 纠正累积每满 20 条，调用一次模型把纠正压缩为泛化偏好文本（如"压缩包类安装文件用户倾向放 软件/安装包 而非 下载/归档"），合并进稳定前缀。偏好文本有长度上限（建议 800 token），超限时要求模型合并压缩。
- 大扫除完成后追加一次调用：把整理结果喂给模型，反推泛化归类原则作为 day-one 偏好。

## 依赖的前置改造

以下改造服务于守门人但同时改善现有功能，须先行完成：

1. **逐项回退**：`rollback/service.py` 从全盘阻断（`can_execute = not blocking_errors`）改为 per-action `skippable + reason`，报告如实呈现"已回退 N 项 / 无法回退 M 项及原因"。守门人时间线的单项撤回直接复用。
2. **journal write-ahead**：去掉 `JOURNAL_CHECKPOINT_INTERVAL`，每条 move 执行前先落盘意图、执行后标记结果。对账机制要求 journal 绝对可信。
3. **journal 文件身份字段**：size + mtime + 小文件 hash，服务纠正采集的跨改名追踪。

## 实施阶段

| 阶段 | 内容 | 预估 |
| --- | --- | --- |
| G0 | 前置改造三项（逐项回退、write-ahead、身份字段） | 3~5 天 |
| G1 | 时间线 + 单项撤回 + 托盘常驻与每日摘要 | 1 周 |
| G2 | 扫描器 + 可移动性门 + 判定调用 + 影子模式 + 熔断降级 | 2 周 |
| G3 | 实弹开关 + 纠正采集 + 偏好沉淀 + 大扫除交接 | 1~2 周 |
| G4 | 精度仪表盘 + 阈值校准闭环 | 持续 |

依赖严格串行：G0 → G1 → G2；G3 三条线可并行。

## 成立标准

连续两周满足：自动移动纠正率 < 5%，且用户未关闭守门人。

达标 → 守门人可作为默认开启能力推进；不达标 → 优先解决判定质量，不加新功能。

## 主要风险

| 风险 | 缓解 |
| --- | --- |
| 位置反推在"改名 + 挪动"叠加时误判 | 身份字段三元组（size/mtime/hash）；不确定时放弃该条纠正而非猜测 |
| 影子期用户没耐心反馈 | "对/不对"必须单击级；即使零反馈，实弹后的纠正采集仍能校准 |
| 自报置信分布随模型切换漂移 | 精度表按模型标识分桶；切换模型后阈值回到保守初始值重新校准 |
| 冷却期与用户期待冲突（"为什么还没整理"） | 时间线呈现"冷却中，将于 X 后处理"，克制可见 |
